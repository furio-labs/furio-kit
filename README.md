# furio-kit

Enterprise React boilerplate by [FurioLabs](https://furiolabs.com). Built on Next.js 16 App Router with React Server Components, Feature-Sliced Design, and a pluggable UI kit behind one `#ui-kit` alias. It targets low-bandwidth users: read-only pages ship only the Next.js framework floor (~132 KB gzip), and CI enforces a per-route JavaScript budget.

**Author:** [Sandro A. Gomez Araya](https://github.com/sandrogomez)

## Bootstrap a new project

```bash
pnpm dlx degit furio-labs/furio-kit my-app
cd my-app
cp .env.example .env.local
pnpm install
pnpm dev
```

Open [http://localhost:3000](http://localhost:3000).

## Requirements

- Node.js 22+ (24 LTS recommended — see `.nvmrc`)
- pnpm 12+

## Starter content (delete when you begin)

furio-kit ships with a working `user` entity as a reference implementation. It demonstrates the complete FSD pattern — Zod schema, fetch function, Server Component, tests, and Suspense streaming.

**Before building your app, remove it:**

```bash
rm -rf src/entities/user
rm -rf src/features/auth    # if you're wiring a real auth provider instead
```

Then update `src/views/home/ui/HomePage.tsx` (rendered by `app/(app)/page.tsx`) to point to your own content. If you removed `features/auth`, also replace `app/(auth)/login/page.tsx`, which renders its `LoginForm`.

Everything else (providers, adapters, auth scaffolding, generators) stays.

## Connecting your design system

UI primitives come from a UI kit selected by one line in `package.json`:

```json
"imports": { "#ui-kit": "./src/shared/ui/kit/default/index.ts" }
```

The default kit is a Tailwind placeholder. Point the alias at your own kit, either as source in `src/shared/ui/kit/<name>/` (for example generated by shadcn/ui or an AI design tool) or as a file that re-exports your `@org/ui-kit` package. The kit must satisfy `src/shared/ui/kit/CONTRACT.md`. A missing export fails `tsc` and `next build`, never production. See [docs/wiki/04-design-system.md](docs/wiki/04-design-system.md).

## Auth

Auth scaffolding lives in `src/shared/auth/`. `AUTH_PROVIDER` (`mock` | `auth0` | `ping`) selects the adapter. The mock adapter is for development and returns no session in production. To activate a real provider:

1. Install its SDK (see the adapter file in `src/shared/auth/adapters/`)
2. Set `AUTH_PROVIDER` and the provider's env vars (see `.env.example`)

See [docs/wiki/05-auth.md](docs/wiki/05-auth.md).

## Security

Vulnerability scanning runs automatically on every push and PR via GitHub Actions (`.github/workflows/ci.yml`). Dependabot opens weekly PRs to keep dependencies current (`.github/dependabot.yml`).

To audit locally:

```bash
pnpm audit
pnpm audit --fix   # auto-fix where possible
```
